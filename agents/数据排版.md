# 数据排版

## 基本原则

- 只使用一次且表达式清晰的值直接写在使用处，不创建仅用于转交的临时变量。
- 表达式较长、具有业务含义、需要复用或能显著提升可读性时，应提取为命名准确的变量。
- 可选对象或数组的初始值优先使用空对象、空数组，避免把演示数据或隐式业务数据写入默认值。
- 必须存在的业务默认值应集中放在配置或工厂函数中，不为了满足“空默认值”而破坏正确行为。

## 声明组织

- 同一职责下确实存在多组数据时，可按数字、字符串、布尔值、数组、对象的顺序排列，或按更清晰的业务职责排列。
- 不添加 `//数字`、`//字符串`、`//数组` 等没有业务信息的空分区注释。
- 数据量较少时保持紧凑，不为了形式制造分区和空行。
- 静态配置与响应式状态分开维护；能由现有状态计算得到的数据使用 `computed` 或纯函数，不再维护一份可变副本。

## 列表与配置

- 列表项使用结构一致、字段含义清楚的对象，例如 `{ key, label, value }` 或 `{ name, icon }`。
- 同一名称同时承担资源名、展示名或业务标识时，优先由一份名称数据生成其他字段，避免维护两份同步映射。
- 静态配置集中声明并保持只读使用，不在业务流程中临时修改共享配置。
- 默认对象需要每次创建独立实例时使用工厂函数，避免多个调用方共享同一可变引用。
- 数组的筛选、排序、映射结果属于派生数据时，从源列表生成；不要在源列表和结果列表之间手动同步相同字段。

```ts
const platformList = ["AI", "ASK", "CP"].map((name) => ({
  name,
  icon: new URL(`../../assets/platform/${name}.webp`, import.meta.url).href,
}));

const createDefaultForm = () => ({
  username: "",
  roles: [],
});
```

## 避免无效中间值

```ts
//不推荐：变量只负责转交且没有增加语义
const defaultVisible = true;
const visible = ref(defaultVisible);

//推荐
const visible = ref(true);
```
