# 注释规范

## 基本原则

- 注释统一使用中文，说明业务目的、边界、原因或非直观行为，不复述代码表面含义。
- 函数、变量和类型默认按需注释；名称与上下文已经自解释时，不要为了形式补充注释。
- 下方强制注释白名单优先于“按需注释”原则，命中白名单时必须补充。
- 原有注释语义清晰且仍然正确时，不得擅自删除、替换或改写原意；仅在缺失、错误、过期或与实现冲突时修正。
- 修改错误或过期注释时，应以当前业务行为为准，不保留会误导维护者的描述。

## 强制注释白名单

1. 直接导出的配置对象或工具对象使用 `/** @description xxx */` 注释。
2. `interface` 中的每个属性使用 `/** xxx */` 注释。
3. 所有 `ref` 变量使用 `/** xxx */` 注释，包括 DOM、组件实例、基本类型、对象和数组引用。
4. Template 中需要说明业务边界或复杂交互的功能模块必须添加模块注释，且注释前空一行。
5. 构造函数中的业务类实例化语句 `new Xxx()`，上一行使用中文 `//` 注释说明实例用途；`Date`、`Map`、`Set`、`Promise` 等通用内建对象不强制。
6. 函数内部存在复杂算法、多阶段流程、特殊兼容或业务分支时，在对应代码块上方使用中文 `//` 分段说明。

## 注释格式

- 自定义函数需要注释时，使用 `/** @description xxx */`；有参数或返回值需要解释时，继续使用 `@param`、`@returns`。
- 类、类型或接口需要整体说明时，使用 `/** @description xxx */`。
- 普通变量或对象需要注释时，使用 `/** xxx */`。
- `//` 后不加空格，例如 `//计算分页数据`。
- 多行 JSDoc 的说明、参数和返回值各占一行，不将多个标签挤在同一行。

```ts
/** 用户名 */
const username = "";

/** @description 获取用户信息 */
const getUserInfo = (username: string, age: number) => {};

/** @description 用户信息 */
interface UserInfo {
  /** 名字 */
  name: string;
  /** 年龄 */
  age: number;
}

/** @description 查询用户 */
const findUser = (id: number) => {
  //先读取缓存，避免重复请求
  const cachedUser = userCache.get(id);
  if (cachedUser) return cachedUser;

  return requestUser(id);
};
```

## Vue 注释

- Vue 生命周期不需要添加注释。
- `defineProps`、`defineEmits`、`defineModel`、`defineOptions` 等 Vue 宏上方不添加说明宏用途的注释。
- `useRouter`、`useRoute` 上方不添加 JSDoc 注释。
- Vue 监听器需要说明时，使用普通块注释 `/* xxx */` 或行注释，不使用 `@description`。
- 不要在 `<template>` 开始标签后的第一行放置注释，避免影响路由页面渲染。
- Template 模块注释必须描述业务含义，例如 `<!--订单明细-->`，不得使用 `<!--模块: div-->` 等无意义描述。

```vue
<template>
  <div class="order-page">
    <OrderToolbar />

    <!--订单明细-->
    <OrderList :data="orderList" />
  </div>
</template>
```

## 禁止事项

- 不要在函数调用上方添加“调用某函数”一类注释。
- 不要给自解释的赋值、返回语句或简单条件分支添加复述性注释。
- 先声明后统一导出的变量，不要仅因导出就在声明上方补充导出说明；只有 `export const` 等直接导出的对象命中强制规则。
- 不要用注释掩盖不清晰命名；能够通过准确命名表达语义时，先优化命名。
